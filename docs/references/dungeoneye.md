## Reliability and adoption

- Useful concepts: one party cell/facing, corner-specific ground items, item-to-target combat, projectile traversal, and authored spell metadata. The reference uses six formation slots; Rifles currently proposes four. Consult the behavior without inheriting that roster limit or the reference runtime.
- Treat donor combat/AI as scaffolding, not behavioral authority. `Monster.Attack` is an unconditional `return false` at `/home/research/blobber-games/dungeoneye/Game/Monster.cs:225-235`; `Square.AddMonster` has the same unreachable insertion body at `/home/research/blobber-games/dungeoneye/Game/Square.cs:480-518`.
- Size is declared only as an unused `MonsterSize` enum (`/home/research/blobber-games/dungeoneye/Game/Monster.cs:2179-2200`); no `Size` property or capacity enforcement exists. `FillSquare` and `BackRowAttack` are loaded fields but unused. `Monster.Move` mutates a temporary `Location` copy (`/home/research/blobber-games/dungeoneye/Game/Monster.cs:85-139,1450-1458`), so cross-cell AI movement cannot be trusted.
- Missing or unreliable details include pathfinding, admitted simulation timers, ranged target selection/line of sight, projectile miss/impact policy, range penalties, size damage variants, critical multipliers, monster attacks, casting-time enforcement, and most healing spells. `IItem` callbacks are declared (`/home/research/blobber-games/dungeoneye/Interfaces/IItem.cs:27-73`) but transfers only notify the square actor, not the item script. Keep these as Rifles design work rather than inferred donor behavior.
